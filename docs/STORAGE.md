# 本地与云端存储规则

## 默认路径

Mac 接收根目录：~/Downloads/FernDrop；Windows 建议 D:\文件传输，首次运行可选择。根目录不在源码目录内。

```
FernDrop/
  2026-09-05/
    .ferndrop-managed
    说明.docx
    说明 (1).docx
    截图.png
  大文件/
    归档.zip
```

日期采用接收端本地时区 yyyy-MM-dd，发送源文件也先复制到受管目录形成稳定副本。普通发送和接收使用同一目录策略。批量总大小 >20 MB 时所有文件归大文件目录；在大文件页手动选择的内容也归这里。原始源文件保持不变。

## 文件提交

净化斜杠、反斜杠、冒号、控制字符和危险内部标记名；保留扩展名，长度限制 180 字符。Windows 额外处理 CON/PRN/AUX/NUL/COM1…LPT9 与末尾点/空格。

重名追加 (1)、(2)…；多任务在一个串行文件提交队列执行；不能“检查后直接覆盖”。Mac 先写 .ferndrop-incoming-UUID，成功后 moveItem 到独占目标；文件选择复制操作本身禁止覆盖。Windows 用 CreateNew/无覆盖 Move。失败临时文件在 defer/finally 移除。

大文件使用 sendme 专用工作目录接收，协议校验完成退出码为 0 后移动至大文件目录，再进入可复制状态。仍在接收的半成品不写进系统剪贴板。

## 清理

每天检查一次，启动补执行。删除根目录下日期严格早于“本地今天 -30 个自然日”的应用受管目录；等于 cutoff 的目录当天保留。只有真实目录且存在 .ferndrop-managed 标记才处理；跳过符号链接。比较保护路径时先归一化 macOS /var 与 /private/var 等别名。

当前文件剪贴板引用、正在发送/接收、待发队列引用的文件保护到引用释放。遇到占用/权限错误跳过，后续重试。大文件目录永远不自动清理；其他自建目录不清理；不跟随链接递归到外部路径。

App Support 的 outbox 密文和 sendme 临时工作目录另按 30×24 小时清理过期且未运行的任务目录；最终大文件不在此处。日志每任务最多保留末尾 16 KB。所有源文件、另存副本不属于清理范围。

当前历史 JSON 留存文本和元信息，日期清理删除的是受管文件副本；文件被清理后点击复制会明确提示不可用。更改根目录不迁移旧文件，也不会在后台继续清理旧根目录，此行为必须在文档中明确。

## 云端

只保存 AES-GCM envelope，文本/图片/小文件/大文件票据均加密。72 小时从服务端首次成功提交起算，重试和下载不延期。最大 200 MB 按密文实际字节计，包括文件 base64 包装；这是空间总上限，不是单文件大小上限。满额返回 507，保留本地待发队列，不淘汰未过期数据。

每分钟清理，且任何认证请求前先清理。失效文件不允许 GET。不要为正文目录额外设置长期云备份，否则三天保留约定不能成立。云端清理不删除本地副本。
